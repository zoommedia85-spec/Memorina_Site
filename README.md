# Memorina: الموقع مع Supabase

## الفولدرات

| الفولدر | الاستخدام |
|---|---|
| `site/` | **ده الوحيد اللي بيتنشر** (يتحط في الريبو / Cloudflare) |
| `supabase/schema.sql` | بيتشغّل مرة واحدة في Supabase، وميتنشرش |
| `import/import-data.json` | بياناتك الحالية (منتجات وصور) لمرة واحدة، **ميتحطش في الموقع** (Cloudflare بيرفض أي ملف أكبر من 25MB) |

محتوى `site/`: الموقع (`index.html` + `app.js`)، ولوحة التحكم (`admin.html` + `admin.js`)، و`config.js` (ربط Supabase)، و`_headers` (حماية المتصفح).

## الإعداد (مرة واحدة)

1. اعمل مشروع على supabase.com. من `SQL Editor` الصق محتوى `supabase/schema.sql` كله وشغّله.
2. `Authentication > Sign In / Providers` وقفل **Allow new users to sign up**.
3. `Authentication > Users > Add user`: إيميلك وكلمة سر قوية (علّم Auto Confirm). بعدها في SQL Editor:
   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'your@email.com';
   ```
4. افتح `site/config.js` وحط `Project URL` و `anon public key` (من `Project Settings > API`).
5. انسخ **محتويات `site/`** جوه فولدر الريبو `memorina-site` (وافق على استبدال `index.html` القديم)، وبعدها:
   ```
   git add .
   git commit -m "backend version"
   git push -u origin main
   ```
6. افتح `https://موقعك/admin.html`، سجّل دخول، وفعّل التحقق بخطوتين (QR بتطبيق Google Authenticator). من غيره مفيش دخول.
7. من لوحة التحكم افتح تبويب **استيراد**، واختار `import/import-data.json`، وادوس **ابدأ الاستيراد**. هيرفع الصور وينقل الكوليكشنز والمنتجات وآراء العملاء (بياناتك الحالية كلها). محتاج دقيقة تقريبًا، ومتقفلش الصفحة.
8. **امسح الـ Google Apps Script القديم** (من script.google.com ثم Deploy ثم Manage deployments ثم Archive)، لأن رابطه كان مكتوب في `index.html` القديم وفي تاريخ الريبو.

## التعديل من لوحة التحكم

أي حفظ بيروح للداتابيز مباشرة. الموقع بيقرا البيانات من الداتابيز **كل ما حد يفتح الصفحة أو يعمل Refresh**، فمفيش push ولا رفع ملفات: احفظ في اللوحة وبعدين اعمل Refresh للموقع وهتشوف التغيير. (اللي فاتح الموقع بالفعل بيشوفه بعد ما يحدّث الصفحة.)

| التبويب | تعمل فيه إيه |
|---|---|
| **الطلبات** | كل طلب بيتسجل برقم. غيّر الحالة وضيف ملاحظة، وفلتر، وصدّر CSV |
| **الكوليكشنز** | إضافة / تعديل الاسم والوصف وصورة الغلاف، **إخفاء الأسعار** للكوليكشن كله، إخفاء الكوليكشن من الموقع، حذف. تغيير الاسم بيتغير في الكروت وفي القائمة فورًا |
| **المنتجات** | الاسم والوصف والصور (أكتر من صورة)، التسعير (سعر ثابت / أحجام / كمية بالجملة)، **Ribbon** ونص ولونه، **إخفاء السعر**، إخفاء المنتج |
| **الشحن** | أسعار المحافظات (ضيف / عدّل / امسح ثم حفظ) |
| **آراء العملاء** | رفع وحذف الصور |
| **إعدادات عامة** | رقم الواتساب، الإنستجرام، العملة، لينك المراجعات |
| **استيراد** | نقل البيانات القديمة (مرة واحدة) |

**اللي لسه بيتعدّل من الكود مش من اللوحة:** النصوص الثابتة في الصفحة (عنوان الهيرو، "من نحن"، الفوتر) والألوان والتصميم. ده في `index.html`، وبعد التعديل بتعمل `git push`.

## الأمان

- الأسعار والتفاصيل في الداتابيز. الزائر ميقدرش يقرأ أو يكتب في أي جدول، وبس بينادي على دالتين: `get_catalog` و `create_order`.
- **السعر بيتحسب على السيرفر.** الموقع بيبعت المنتج والكمية، والسيرفر بيحسب من الأسعار الحقيقية. تعديل السلة من المتصفح مبقاش بيفيد. والأسعار المخفية **مش بتتبعت للمتصفح أصلًا**.
- الأدمن لازم يكون في جدول `admins` **ومعاه تحقق بخطوتين**، والصلاحية مفروضة من الداتابيز مش من الواجهة.
- فحص كل المدخلات على السيرفر، وحد للطلبات المتكررة، وحقل مخفي للبوتات.
- كل النصوص بتتعمل لها escape (ثغرة XSS في البحث اتقفلت)، ومفيش `onclick` في الكود، وفيه CSP صارم ومنع الـ iframe وHSTS.
- الصور في Storage (رفع وحذف للأدمن بس)، وبتتضغط تلقائيًا قبل الرفع.
- بيانات العميل في المتصفح في `sessionStorage` (بتتمسح بقفل التبويب)، والسلة من غير أسعار.

## ملاحظات

- الأسعار المخفية: الإجمالي في السلة بيظهر "بيتأكد مع التيم" لو كل الأصناف مخفية السعر.
- لو فئتين كمية متداخلتين (زي 15–50 و 50+) بيتطبق الأرخص عند الرقم المشترك.
- أوصاف المنتجات بتحترم الأسطر الجديدة.
- قسم آراء العملاء بيختفي لو مفيش صور.
- لو ظهرت طلبات وهمية كتير، فعّل Rate Limiting من Cloudflare.
- قبل الإطلاق جرّب طلب تجريبي كامل (منتج عادي + منتج سعره مخفي) وتأكد إنه ظهر في تبويب الطلبات.
